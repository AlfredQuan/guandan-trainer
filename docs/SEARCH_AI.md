# 可见信息采样搜索 v0.18

目标：利用记牌器提高实际决策质量，再决定是否用搜索结果训练学生模型。原 TypeScript 引擎裁定掼蛋规则；大规模评测和训练使用 Kaggle CPU。

## 决策

未见牌池 = 两副 108 张实体牌 − 本人当前手牌 − 公开已出牌。按三家公开剩牌数采样归属，重建行动位、最后压牌、连续过牌次数和出完顺序，支持四座位。过牌是可选行为，不当成必定无牌可管的硬证据。

保留冻结结构策略动作，补充过牌和低拆牌代价候选；等价实体副本只评一次，保留逢人配声明。最多 4 个候选共享 12 个样本，冻结结构策略续打至头游产生。候选配对增益超过保守的有限样本选择阈值才替换基线。该阈值是选择启发式，不是实际牌局胜率区间。

本人不超过 12 张、全桌不超过 48 张才搜索。搭档当前领牌、可以直接出完、已有头游或单一选择时沿用基线。均匀暗牌先验尚未按历史行为更新；代表候选与结构续打也不保证数学最优。抽样结果不是已校准的实时胜率。

## 评测

开发集 offset 6500000：40 副换边 80 局，级牌覆盖 2–A；参数固定后独立测试 offset 6600000：240 副换边 480 局，Kaggle CPU。每副换边作为一个统计单位，保存头游率、升级差、配对区间、保守 Hoeffding 界限、非法动作、搜索及改选次数、耗时和每副结果。

## 接入

构建后设置 GUANDAN_AI_PROVIDER_MODULE 为 offline/search-provider.mjs 的完整路径，再启动 offline/ai-server.mjs，Arena 选择“本机接口”。未设置实验提供者时沿用原结构策略。动作仍由网关和规则引擎验证；这里只在本机推理，不启动本机训练。

交付包 kaggle-search-v018/evaluate.py 嵌入冻结引擎及哈希，使用既有私有数据集中的官方 Node 运行时，关闭互联网和 GPU。API token 不进入脚本或源码。

## 验证

search-ai-smoke.ts 覆盖公开状态重建、实体牌守恒、暗牌置换不变、配对样本、确定性、整局合法性。完整离线回归还覆盖规则、接风、逢人配声明、理牌、复盘、网关、神经接口、自博弈和单文件 UI。

## 本轮实测结果

Kaggle CPU 独立留出 240 对、480 局：258 胜，头游率 53.75%，升级净差 +58，非法动作 0；3142 次搜索、185 次改选。4 个执行分片的决策 P95 为 98–111 毫秒，最大单步约 1.22 秒。

240 对中，22 对两局都胜、4 对两局都负、214 对各胜一局。补充的双侧精确配对符号检验 p=0.0005335，支持正向收益。此补充检验不改变冻结的部署规则；头游率仍低于预设 55%，保守 Hoeffding 区间也跨越 50%，默认策略未替换。

开发集 44/80 胜（55%），决策 P95 227 毫秒，最大约 1.15 秒。云端和本机硬件不同，耗时不能直接比较。两套数据均按同副换边配对，开发集与留出集无种子重叠。

报告下载后已独立核对全部 240 副种子、双方换边、胜局、升级差、分片聚合、非法动作和冻结引擎 SHA-256。完整离线回归及 HTTP 实验提供者验证通过。源码与运行包包含可选搜索提供者，方便试玩与下一轮云端教师数据实验。
