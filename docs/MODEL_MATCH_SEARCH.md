# v020：神经模型与公开信息整局搜索

v019 已在 Kaggle CPU 完成 800 副训练、160 副验证、6 轮参数优化，共 17068 行训练样本，含 700 个搜索改进动作。验证选择第 4 轮。独立 240 副换位测试：学生 251/480，原模型 250/480；升级净值 -3 与 +52；头游胜率差 95% 配对常规区间 [-3.61%, 4.02%]。这个结果不能证明提升，学生也不替换默认 AI。

v020 保留原 v017 权重，尝试以搜索复核其残局动作。搜索只接收当前玩家手牌、公共出牌/过牌记录、剩余张数及当前牌面，由记牌剩余牌池随机分配未知手牌；真实对手手牌和种子不进入决策。

每个位置最多 12 个共同采样、4 个候选。候选含神经模型原动作、过牌、规则动作及结构候选；预算严格与服务端的 256 动作一致，保留百搭声明。普通局面、队友领牌、已经有人出完、手牌超过 12 张或全桌剩余超过 48 张时，直接保留原模型。

搜索模拟到整局结束，以 `头游获胜指示 + 0.5 × 胜负符号 × 升级级数 / 3` 评分。候选只有通过配对平均改进和方差门槛才覆盖原动作。此门槛是选择启发式，不能当作真实比赛胜率的置信保证。模拟后续由冻结规则 AI 完成，可能有策略模型偏差。

测试预先冻结：offset=7400000、240 副牌、每副交换双方队伍，每个方案 480 局；v020 和原 v017 都对战同一个规则 AI，四个 CPU 工作进程。它是同对手配对比较，不是 v020 与 v017 直接交锋。

私有 CPU 评测：https://www.kaggle.com/code/alfredq/guandan-neural-public-match-search-v020

服务接口沿用既有 `ai-server.mjs`，可选 provider 为 `model-search-provider.mjs`。包内模型 `runtime/models/v017.json` 为冻结原模型，`runtime/models/v019-experimental.json` 为未证明提升的蒸馏候选。启用 v020 时加载前者。

PowerShell 示例（在解压后的包目录运行，Node.js 必须可用）：

```powershell
$env:GUANDAN_AI_MODEL = (Resolve-Path './runtime/models/v017.json').Path
$env:GUANDAN_AI_PROVIDER_MODULE = (Resolve-Path './runtime/offline/model-search-provider.mjs').Path
node ./runtime/offline/ai-server.mjs
```

默认端口 17364，游戏的外部 AI 接口沿用原流程。此脚本只运行推理，不在本机训练。默认内置规则 AI 保持原状。完整测评结果见随包的 evaluation-report-v020.json。

## 最终实测（已核验）

240 副独立牌、每副双方换位，双方各 480 局，对手均为冻结规则 AI。v020 头游 262/480（54.58%），原 v017 226/480（47.08%）；配对差 +7.50 个百分点，常规 95% 配对区间 [4.83, 10.17] 个百分点。升级净值分别 +80 与 -58，差 +138；每局配对升级收益 +0.2875，常规 95% 区间 [0.1804, 0.3946]。较保守的 Hoeffding 头游差区间 [-10.03, 25.03] 个百分点仍包含零。

采样搜索 2993 次，改动原模型动作 240 次；非法动作 0；四个 CPU 分片 p95 为 167.6–173.0 ms，最大 1.56 s。CPU 云端整轮评测耗时 178 秒。源包、原模型哈希、240 副种子与双方换位记录、聚合结果均重新校验通过。

默认部署门槛未通过：头游胜率 54.58% 尚低于 55%，95% Hoeffding 下界 45.82% 尚未超过 50%。因此交付为可选实验 AI，默认规则策略不变。这里的 7.5 个百分点提升是对同一规则对手的比较，不是 v020 对 v017 的直接交锋胜率；也不表示蒸馏权重获得了已证明的改进。
