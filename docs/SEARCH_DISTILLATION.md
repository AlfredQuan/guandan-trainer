# v019：公开信息搜索蒸馏

目标是把 v018 采样搜索中经过对战验证的决策经验，压缩进 v017 的 155 → 64 → 1 动作网络。全部数据生成、大规模对战和 PyTorch 参数训练在私有 Kaggle CPU 任务执行。本机仅构建、测试和推理。

## 冻结实验设计

- 初始和对照模型：WorkBuddy 导出的 v017 `model.json`。
- 教师：v018 `decideSearch` 默认预算，12 个公共记牌约束的未知手牌采样，最多 4 个候选；以配对收益和方差门槛决定是否更改规则动作。
- 数据：800 副训练牌、160 副验证牌；四个座位、级牌 2..A。交替使用搜索教师和原模型走完整对局，缓解训练状态与模型实际状态之间的差异。
- 全部搜索位置都保留，普通位置每 8 步采一个锚点。目标必须属于实际推理时 256 候选动作；超出预算的标签跳过并计数。候选按 `actionKey` 排序，显式百搭牌型声明保留。
- 网络维持 155 → 64 → 1，tanh；AdamW，学习率 0.00015、6 轮、batch 32。搜索改变的标签 CE 权重 12，其他为 1；对原模型 KL 权重分别为 0.02 和 0.2。
- 2/4/6 轮检查点与原模型均参加 80 副验证对局，每副交换队伍，共 160 局。先按头游胜局数、再按升级净值选检查点，完全相同保留较早的模型。
- 最终一次性测试选中模型与原模型：相同的 240 副新牌、两次换位，共每个模型 480 局；对手固定为原规则 AI。差值是对同一对手的配对比较，不能解读为学生与原模型直接交锋胜率。

种子空间由 `seed = 7001 + (offset + index) * 7919` 固定：训练 7000000、标签验证 7100000、选型对局 7200000、最终测试 7300000。训练行使用随机 dealId，不包含种子或真实对手手牌。

## 验证和部署条件

每步都由原引擎检查合法性和 108 张实体牌守恒；Python 校验特征、目标下标、四座位和分组隔离。每个候选检查点执行 Python/JavaScript 推理分数一致性检查。云端报告保留原模型/新模型 SHA256、引擎 SHA256、配置、训练历史、每副测试结果和丢失标签计数。

延续原有默认部署门槛：至少 200 副配对、头游胜率至少 55%、95% Hoeffding 下界超过 50%。实验结果不满足时，默认仍为规则 AI。模型可以通过现有 `neural-provider.mjs` 单独试用。

CPU 任务：https://www.kaggle.com/code/alfredq/guandan-search-distillation-v019

## 复现入口

`offline/search-distill.ts` 是公开视角标签生成器，`offline/search-distill-smoke.ts` 是动作索引、非法标签、公开视角及完整对局回归检查。云端脚本和冻结引擎在 Codex 交付目录的 `kaggle-distill-v019` 下，提交命令为 `kaggle kernels push -p <目录>`。认证从外部环境变量注入，不能写入脚本。

选中的 `model.json` 遵守现有 NeuralModel 格式，可使用现有神经网络 provider 加载。最终能力结论以训练报告和全新牌副的测试为准，不能以模仿准确率代替对战结果。
